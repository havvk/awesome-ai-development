# 本地自动化导演：Codex CLI

Codex CLI 将大型语言模型直接嵌入到本地开发环境中，它既可以像 Copilot 那样辅助写代码，又能像脚本引擎一样执行真正的命令行操作。通过对话式交互生成计划、执行命令并实时回传结果，Codex 更像是一位“能动手的结对程序员”。

### 核心能力

1.  **结构化任务规划**
    *   **特点:** 输入需求后，Codex 会先产出可审查的步骤计划，再逐步执行。计划预览让你能在破坏发生前就刹车。
    *   **价值:** 避免“黑盒式”自动化，把每一步变成显式选择，尤其适合需要强控制的场景。

2.  **命令级自动化执行**
    *   **特点:** Codex 能在本地终端中运行 git、npm、pytest 等命令，执行结果会即时回写到对话中。
    *   **价值:** 用自然语言驱动命令行，把“想法 -> 命令 -> 结果”串成闭环，减少上下文切换。

3.  **文件编辑与补丁审阅**
    *   **特点:** 所有文件改动都会以 diff 形式呈现，你可以逐块接受或退回，再让 Codex 继续调整。
    *   **价值:** 将 AI 生成的代码纳入正常的 review 流程，保持可追溯性与可回滚性。

4.  **多代理协作**
    *   **特点:** 在 Codex CLI 中可以按照任务拆分出多个 agent，让它们针对不同目录或角色工作。
    *   **价值:** 大型特性开发时，把“重构”“文档”“测试”拆开处理，互不干扰。

### 典型工作流

1.  **多文件重构**
    *   **流程:**
        1.  在终端启动 `codex`，描述目标重构。
        2.  让 Codex 生成计划并确认受影响的文件列表。
        3.  审阅每个 diff，必要时用“继续修改”指令迭代。
        4.  自动运行测试命令验证。
    *   **亮点:** 通过显式计划+逐块 diff，把复杂修改控制在可理解范围。

2.  **快速原型搭建**
    *   **流程:**
        1.  在空目录或新分支中，让 Codex 初始化框架、安装依赖。
        2.  用自然语言描述接口和组件，由 Codex 生成基础实现。
        3.  使用 `plan`/`run` 循环补齐样板代码与脚手架脚本。
    *   **亮点:** 节省重复劳动，但所有关键逻辑依然由人类把关。

3.  **CI/CD 流程试跑**
    *   **流程:**
        1.  将 `.codex/config.json` 中的审批策略设置为严格模式。
        2.  让 Codex 模拟 CI 步骤（构建、单测、静态分析）。
        3.  根据输出调优脚本，再次运行至通过。
    *   **亮点:** 在本地复现流水线，提前捕获脚本回归。

### IDE 集成技巧

*   **VS Code:** 在终端内运行 Codex CLI，并用 `code .` 打开同一目录。Codex 推送的文件改动会立即出现在 VS Code 的 Source Control 面板，便于逐行确认。
*   **JetBrains:** 通过“Terminal”视图运行 Codex，将其与 IDE 的“Local History”结合使用，可以在“Compare with Local History”中查看 AI 改动轨迹。
*   **多会话切换:** 结合 `codex session list` 与 `codex session attach`，在不同特性或热修复之间快速切换上下文。

### 最佳实践

*   **先问再让它动手:** 在需求不明确时，先让 Codex 给出它的理解和计划，再决定是否执行。
*   **限定作用域:** 上来就告诉它相关目录、配置文件位置以及禁区，减少误伤。
*   **每次提交前手动检查:** Codex 不是托管人；保持本地运行测试、手动 review 的习惯。
*   **善用审批模式:** 通过 CLI 的 `on-request` 或 `never` 策略限制高危命令，必要时手动放行。

Codex CLI 不是“全自动驾驶”，而是把命令行、编辑器与 AI 连接起来的高效操控台。掌握计划审阅、命令复核和 diff 处理这三个动作，就能在保持掌控的前提下，把繁琐重复的工作交给机器。
